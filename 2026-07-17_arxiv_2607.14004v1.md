## Agent 優化器能複利累積嗎？Terminal-Bench 2.0 上的持續學習評估
英文標題：Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0

作者：Wenxiao Wang, Priyatham Kattakinda, Soheil Feizi
發布日期：2026-07-15
arXiv ID：2607.14004v1
PDF：有

## 英文摘要
Most reported gains from agent-optimization methods are one-shot: an agent is optimized against a fixed benchmark and the improvement is reported as if it were a stable property of the method. This does not test the setting that matters for deployed agents, where optimization is applied recursively as new failures and new tasks appear over time. The central question is whether optimizer-driven gains compound: after an agent has been optimized once, can it be optimized again on newly arrived tasks without eroding the first round's gains? This study uses a two-phase continual-learning evaluation built from hard tasks in Terminal-Bench 2.0, comparing three approaches (GEPA, Meta Harness, and RELAI-VCL) under identical optimization budgets. All three methods improve over the baseline in the static single-phase setting. However, once new tasks are introduced, the methods diverge sharply: GEPA's optimized agent transfers below the unoptimized baseline, Meta Harness transfers well but fails to improve further, and RELAI-VCL is the only method that both transfers positively to unseen tasks and continues improving after those tasks are folded into the optimization objective, reaching the highest pass rate at every stage (76.4% vs. 66.0% for GEPA, 64.6% for Meta Harness, and 58.7% for baseline). The key observation is that optimization gains compound only when regression control is built into the optimization loop.

## 繁體中文摘要
大多數 agent 優化方法的報告成果都是一次性的：agent 針對固定基準進行優化，改進被報告為方法的穩定屬性。但這並未測試已部署 agent 的實際場景——在這些場景中，優化隨著新失敗與新任務出現而遞迴應用。核心問題是：優化帶來的增益能否複利累積？在 agent 被優化一次後，能否在新任務上再次優化而不侵蝕第一輪的成果？本研究使用 Terminal-Bench 2.0 中困難任務構建的兩階段持續學習評估，在相同優化預算下比較三種方法（GEPA、Meta Harness、RELAI-VCL）。三種方法在靜態單階段設置中均優於基線。然而，一旦引入新任務，方法之間出現顯著分歧：GEPA 的優化 agent 遷移效果低於未優化基線；Meta Harness 遷移良好但無法進一步提升；RELAI-VCL 是唯一既能正向遷移至未見任務、又能在那些任務納入優化目標後持續改進的方法，在每個評估階段達到最高通過率（76.4% vs GEPA 66.0%、Meta Harness 64.6%、基線 58.7%）。關鍵發現是：只有在優化迴圈中內建回歸控制時，優化增益才能複利累積。

## 關鍵知識點
- 現有 agent 優化報告多為一次性，未測試持續優化場景
- 核心問題：優化增益能否複利累積而不侵蝕前期成果
- 兩階段持續學習評估：Terminal-Bench 2.0 困難任務
- GEPA 遷移效果低於未優化基線（負遷移）
- Meta Harness 遷移良好但無法持續改進
- RELAI-VCL 唯一達成正遷移與持續改進（76.4% 最高通過率）
- 回歸控制是複利累積的關鍵歸納偏置

## 主要貢獻
1. 首次提出 agent 優化器的「複利累積」問題，超越傳統一次性評估
2. 設計了兩階段持續學習評估框架，揭示方法間在遷移與持續改進上的顯著差異
3. 發現回歸控制是優化增益複利累積的關鍵歸納偏置，為 agent 優化提供設計指引
4. RELAI-VCL 在所有階段達到最高終身平均通過率（76.4%），顯著優於其他方法
5. 為已部署 agent 的遞迴優化提供了可評估的基準與方法論

## 原始摘要（English）
Most reported gains from agent-optimization methods are one-shot: an agent is optimized against a fixed benchmark and the resulting improvement is reported as if it were a stable property of the method. This does not test the setting that matters for deployed agents, where optimization is applied recursively as new failures and new tasks appear over time. The central question this raises is whether optimizer-driven gains compound: after an agent has been optimized once, can it be optimized again on newly arrived tasks without eroding the gains the first round produced? We study this question with a two-phase continual-learning evaluation built from hard tasks in Terminal-Bench 2.0, comparing three approaches to agent-harness optimization (GEPA, Meta Harness, and RELAI's Verifiable Continual Learning, RELAI-VCL) under identical optimization budgets. All three methods improve over the baseline agent in the conventional, static, single-phase setting. However, once new tasks are introduced, the methods diverge sharply: GEPA's optimized agent transfers below the unoptimized baseline, Meta Harness transfers well but fails to improve further once given a second optimization budget, and RELAI-VCL is the only method that both transfers positively to unseen tasks and continues improving after those tasks are folded into the optimization objective, reaching the highest pass rate at every evaluated stage and the highest lifelong average pass rate overall (76.4% vs. 66.0% for GEPA, 64.6% for Meta Harness, and 58.7% for the baseline). Our key observation was that optimization gains compounded only when regression control was built into the optimization loop, providing an inductive bias against shortcut solutions that fail to generalize.
